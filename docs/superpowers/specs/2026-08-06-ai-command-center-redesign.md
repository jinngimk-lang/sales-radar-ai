# Sales Radar AI：AI 情报指挥中心重构设计

日期：2026-08-06

## 1. 目标

把当前分散在“市场机会、销售机会、收益控制台、AI 助手”中的核心能力收敛为一个 GPT 式入口：用户输入一句自然语言任务，系统调用现有真实搜索、联系人补全、客户研究、市场研究、收益机会与云浏览器能力，并把结果按业务对象完整陈列。

成功标准：

1. 根路径和工作区默认入口都是对话首页。
2. 首屏只有清晰的任务输入、模型状态和少量可执行示例，不再同时展示多套重复工作流。
3. 一次 Agent 运行后，页面能够展示执行轨迹、对象、公司、公开联系方式、来源证据、商业判断和下一步动作。
4. 一级导航只保留 AI 首页、市场雷达、收益中心和设置。
5. 旧链接继续可访问或重定向，不破坏已有详情页和后台接口。
6. 所有显示为“个人信息”的字段必须来自公开页面或已连接的数据源，带来源、观察时间和验证状态；未观察到的数据明确显示未知，不猜测。

## 2. 产品原则

### 保留

- GPT-5.6 Sol 销售 Agent 与工具编排。
- 真实联网搜索和当前 SearchTask 数据所有权。
- 联系人补全、公司研究、渠道研究、话术生成。
- 市场信号研究、来源浏览和时间线。
- 收益机会、结算证据和 Browserbase Live View。
- 运行能力、模型和数据源状态。

### 删除或降级

- 重复的一级入口和重复标题区。
- AI 助手左侧永久联系人列表。
- 首屏上的手动联系人/话术设置面板。
- 单独的“销售机会”一级导航；该能力成为 AI 首页结果和旧链接兼容页。
- 纯展示、未连接真实数据的统计和装饰性流程条。
- 任何把潜在值、推断值或模拟值表达为事实的文案。

### 不取消的约束

以下不是产品负担，而是系统可信度边界，必须保留：工作区隔离、来源追溯、公开信息边界、密钥不进前端、外部发送需确认、KYC/支付/钱包由用户本人处理、禁止未授权安全测试、禁止伪造互动和收益。

## 3. 信息架构

### `/`、`/app`、`/app/home`

统一进入 `AICommandCenterPage`。

页面结构：

1. 顶部极简栏：产品名、当前模型、数据源状态、历史任务入口。
2. 空状态：居中的大输入框、四个真实能力提示、三条示例任务。
3. 运行状态：输入框固定在底部，主体展示当前对话和工具执行时间线。
4. 结果状态：在 Assistant 回复下方显示结构化结果面板。

### `/app/market`

保留市场研究能力，移除装饰性四步流程条，强化：监控目标、运行状态、网页来源、信号时间线、销售判断。

### `/app/revenue`

保留云浏览器、机会队列、结算与证据。统一标题和间距，把 Live View、机会队列、收益指标和账本按“执行 → 机会 → 结算”顺序排列。

### `/app/account`

保留模型、数据源和工作区运行状态。新增数据可见性说明：哪些字段会展示、从哪里来、何时视为已验证。

### 兼容路由

- `/app/assistant` → `/app/home`
- `/app/dashboard` → `/app/market`
- `/app/discover` 保留为高级结果浏览页，但从一级导航移除。
- 客户、机会和研究详情路由继续存在，供结果卡片钻取。

## 4. AI 首页数据流

1. 用户输入自然语言任务并选择模型。
2. 前端调用现有 `runSalesAgent`。
3. Agent 返回回答、工具动作和 `leadIds`。
4. 前端刷新 `getChatSessions`，按 `leadIds` 选择本次结果；如果 Agent 没有返回 ID，则保留纯回答与动作轨迹。
5. 每个结果对象渲染：
   - 身份：显示名、角色、公司、平台、主页、来源。
   - 公开联系方式：邮箱、电话、社交主页。
   - 联系字段证据：sourceUrl、extractionMethod、observedAt、verificationStatus。
   - 内容与信号：公开内容、沟通偏好、意向/身份/证据/联系人评分。
   - 推荐动作：打开对象详情、补充公开联系人、进入研究、生成触达。
6. 结果只展示 API 返回的字段，不从姓名或域名推算邮箱、电话或身份。

## 5. 组件边界

### `AICommandCenterPage`

管理模型、输入、历史消息、Agent 运行、结果对象和错误状态。

### `CommandComposer`

只负责输入、快捷任务和提交；支持 Enter 提交、Shift+Enter 换行。

### `AgentConversation`

渲染用户/助手消息、运行状态和工具动作；不管理数据请求。

### `IntelligenceResultGrid`

接收 `ChatSession[]`，按对象渲染结果卡片；不负责调用 Agent。

### `EntityIntelligenceCard`

展示身份、公开联系方式、证据、评分、公开内容和钻取动作。

### `SourceEvidenceList`

统一展示来源 URL、观察时间、提取方法和验证状态，避免不同页面重复实现证据 UI。

## 6. 视觉方向

- GPT 式中心布局，最大内容宽度约 1120px。
- 桌面端采用 228px 紧凑侧栏；移动端改为顶部四个图标。
- 主背景为暖白/浅灰，结果卡片使用白色、细边框和克制阴影。
- 品牌蓝只用于提交、选中状态和关键评分；收益页继续使用深色 Live View 区域。
- 不用大面积空白加小卡片居中；运行或有结果时让内容填满可用宽度。

## 7. 错误与空状态

- OpenAI 未配置：显示 Railway 服务端配置提示，不显示“模型在线”。
- 搜索无结果：保留回答和动作记录，明确没有返回可验证对象。
- 联系方式为空：显示“未在允许访问的公开来源中观察到”，不显示占位邮箱或电话。
- 单个联系人证据格式异常：跳过异常证据，其余对象继续渲染。
- 请求失败：保留用户输入，可重试，不清空上一轮结果。

## 8. 测试

前端契约测试必须覆盖：

1. 根路径和 `/app` 默认进入 AI 首页。
2. 一级导航只包含 AI 首页、市场雷达、收益中心、设置。
3. 旧助手和旧市场路径重定向。
4. AI 首页包含单一主输入、GPT-5.6 Sol 模型入口、工具轨迹和结构化结果组件。
5. 个人/联系人字段必须与来源证据同时展示；不存在“猜测邮箱”“自动发送”“全部私人信息”等误导文案。
6. 市场页不再显示装饰性四步流程条。
7. 前端类型检查、测试、生产构建通过；后端现有测试无回归。

## 9. 实施顺序

1. 新建 AI 首页组件和共享结果组件。
2. 调整路由和导航。
3. 简化市场页。
4. 调整收益页布局标题与顺序。
5. 更新说明与测试。
6. 通过 CI 后以 PR 合并并核验 Vercel/Railway 部署。

## 10. 非目标

- 本轮不重写搜索、Agent、市场研究或收益后端。
- 本轮不新增批量外部发送、自动注册、自动登录或自动交易。
- 本轮不把未公开、未授权、无来源的个人信息暴露给前端。
- 本轮不删除旧详情页的数据模型和 API，只降低其导航层级。
